# Future Ideas

## World Spawn (WS)

World Spawn — система управления кэмпами, спавном, деспавном и респавном существ в мире.

### Camps

Кэмп имеет:
- набор координат/слотов для мобов;
- сложность кэмпа;
- доступный пул существ, зависящий от локации;
- сгенерированный состав.

Сила кэмпа определяется бюджетом примерно вида:

camp_budget = camp_difficulty * location_level * rebirth_level

Каждый тип моба имеет свой `weight`.

WS самостоятельно собирает отряд в пределах бюджета и доступных слотов. Повторение одного типа моба становится дороже: например, первый маг может стоить 50 веса, второй — уже 100. Это должно естественно склонять генератор к более сбалансированным отрядам вместо заполнения всех слотов одним сильным юнитом.

### Active Area

Симулируются только существа рядом с игроком.

Active Area ≈ размер камеры + 10–20% запаса с каждой стороны, чтобы существа успевали появиться до того, как игрок их увидит.

Возможно использование двух границ:
- меньшая — spawn/activation;
- большая — despawn;

чтобы существа не spawn/despawn постоянно на самой границе области.

### Despawn / Death

Это разные события.

Despawn:
- игрок ушёл достаточно далеко;
- runtime Entity удаляется ради экономии ресурсов;
- respawn cooldown НЕ запускается;
- при возвращении моб может быть создан снова.

Death:
- моб реально убит;
- Entity удаляется;
- запускается respawn cooldown.

Респаун должен идти по мировому времени даже вне Active Area.

Вместо постоянного тиканья мёртвого моба можно хранить:

respawn_at = world_time + respawn_delay

При возвращении в область WS сравнивает текущее мировое время с `respawn_at`.

## Ranged AI (RAI)

Цель — ranged-мобы должны не просто стоять и стрелять, а активно контролировать дистанцию и кайтить игрока.

### Desired Range

Лучник ищет комфортную позицию внутри своей рабочей дистанции.

Если цель слишком далеко:
- приблизиться.

Если дистанция подходящая:
- остановиться;
- атаковать.

Если игрок подобрался слишком близко (ориентировочно < 0.5 tile):
- небольшая задержка реакции (~3 кадра);
- начать отход;
- восстановить комфортную дистанцию;
- снова атаковать.

### Spacing

Ranged-мобы не должны собираться в одной точке.

Позиция считается подходящей, если:
- она находится на нужной дистанции от цели;
- рядом нет другого ranged-моба примерно в пределах размера его изображения + 15%.

Это должно заставлять группу лучников распределяться вокруг пространства боя.

### Intended Behaviour

Несколько ranged-мобов должны уметь кайтить совместно:

- игрок преследует одного;
- этот моб отступает;
- остальные сохраняют дистанцию и продолжают атаковать;
- преследуемый после восстановления дистанции снова включается в бой.

Важно: ranged positioning — отдельное AI-поведение. Не нужно заставлять дальников использовать melee-surround только ради построения формации.

Итоговая философия RAI:
**если игрок решил просто зажать W в сторону лучника — лучник должен максимально вежливо объяснить ему, почему это была плохая идея.**
